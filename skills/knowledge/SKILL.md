# Notionの情報検索と記録

## 手順

1. `notion.search`と`notion.read`で対象と現在の内容を確認する。
   読取り対象がdata sourceならスキーマと行プロパティを参照し、行の本文が必要なら
   そのページIDで読み取る。
   内部記録を必要としない質問では、この手順を経由する必要はない。
2. 依頼に応じて、新規ページの本文・追記内容・段落の変更案を組み立てる。
   Slackスレッドの記録では会話を整理する。
3. 必要な入力が揃ったら、作成は`notion.create`、追記は`notion.append`、段落編集は
   `notion.update_block`の操作案を返す。
4. 読み取った情報やPythonから返された実行結果を、利用者に回答する。

## 使用例

- 「NotionのKaggleページを探して」：検索し、該当する候補とリンクを返す。
- 「このスレッドをNotionに記録して」：会話を整理して操作案を作る。
  同じスレッドの既存ページがあれば、Python側でそのページへの追記に切り替える。
- 「この段落を修正して」：対象ページ・段落と変更前本文を確認し、変更案を提示する。

## 参加中のコンペの参照

1. 「今参加しているコンペは？」「コンペの概要を知りたい」「残りの提出数は？」など、
   コンペ名が省略された質問も含め、
   `resources.notion_competition_data_source_id`を`notion.read`の`page_id`に指定する。
   未設定ならCompetition DBの設定が必要だと伝え、参照先を確認する。
2. 今回の取得結果の行プロパティから`Status = Active`を抽出し、`Name`・`Kaggle`・`GitHub`を
   回答に使う。`Active`が0件なら、その旨を伝える。複数件あり対象が特定できない依頼は確認する。
   `Finish`や未設定の行は参加中に含めず、取得失敗を0件と扱わない。
   参加中が1件ならそのコンペを対象に進める。特定のコンペ名を明示された場合はその指定を優先し、
   参加状況の確認が不要な公開情報の質問ではCompetition DBを経由する必要はない。
   現在の参加状況は過去の会話だけで断定せず、今回の依頼で再取得する。
3. 行の本文が必要なら、取得した行のページIDを`notion.read`で読む。
   リンクの登録だけではKaggleやGitHubのリンク先本文を読んだことにはならない。
4. 名前やURLの提示だけで元の依頼が終わらない場合は、公開Web調査が有効ならリンク先を調べる。
   例：「残りの提出数は？」→「参加中のコンペ」という会話なら、DBで対象を特定した後に、
   提出ルール・上限と実際の残り枠の確認に進む。コンペ名の紹介だけで終えない。
   公開の提出上限とチームの使用済み提出数・残り枠は区別する。後者を公開検索で推測しない。
