# 予定の照会と調整

## 手順

1. 適用ルールに従ってカレンダーと対象者を特定する。メンバー対応やラベルの一覧が必要なら
   `calendar.list`で取得する。
2. 予定照会は`calendar.events`、空き時間の照会・再確認は必ず`calendar.free`を使う。
   Member DB全員または指定された人の個人ラベル・共通予定の参加者をPythonが選別し、
   重複統合・空き時間計算・
   回答文の生成まで行う。AIが予定一覧から判定したり、計算結果の日時を文章に書き直したりしない。
3. 作成・変更の依頼では、取得結果と会話から必要な入力を確認する。
   入力が揃ったら、作成は`meeting.create`、変更は`calendar.update`の操作案を返す。
   招待する人はMember DBのSlackユーザーIDとCalendar Emailsで確認する。
   Google Meetが必要なら`draft.create_google_meet=true`を指定する。
   `slack.channels`で`10_competition_general`または相当する周知先を確認して、
   `meeting.create`の1操作に予定・招待先・周知文をまとめる。承認はPythonが1回だけ求める。
4. 予定だけの質問なら読み取った結果を回答する。予定を手掛かりに公開情報も調べる依頼なら、
   必要な施設名などを使って調査を続け、元の質問に答える。

## 使用例

- 「次のキックオフはいつ？」：対象カレンダーから予定候補を取得し、日時を返す。
- 「次のミーティングいつ？」への補足が「キックオフ」「カレンダー」：
  同じ依頼の補足として引き継ぎ、候補を探す。
- 「さっきの面談を30分後ろにして」：記憶した予定を取得し、開始・終了を30分ずらした案を提示する。
- 「金曜に面談を入れて」：必要な開始終了日時とタイトルが不足していれば確認する。
- 「10/30の19〜20時に進捗確認。中川と秋山を招待して、generalに@channelで周知して」：
  最新のメンバー対応と許可済みの周知先を取得し、`meeting.create`でまとめて承認を求める。
